# RepoPilot AI Developer Guide

This guide explains how RepoPilot AI is organized and how the current commit
suggestion workflow works. It is written for contributors who want to understand
the code before changing it.

## 1. What RepoPilot AI does

RepoPilot AI is an offline-first command-line tool for Git chores. The current
feature reads the staged Git diff and asks a local Ollama model to suggest one
Conventional Commit message.

The current command is:

```powershell
node .\dist\cli.js suggest-commit
```

The command only suggests text. It does not create a commit, push to a remote,
modify a file, or read untracked files.

## 3. Runtime flow

The commit suggestion path follows this sequence:

```text
User runs CLI
    |
    v
src/cli.ts validates command options
    |
    v
src/git.ts runs git diff --cached --no-ext-diff
    |
    v
src/commit-generator.ts rejects empty input and bounds large diffs
    |
    v
src/commit-generator.ts builds a strict JSON prompt
    |
    v
src/ollama.ts sends the prompt to local Ollama
    |
    v
src/commit-generator.ts parses and validates the response
    |
    v
src/cli.ts prints JSON or a formatted commit message
```

No step writes to the repository. The only external operations are the read-only
Git command and an HTTP request to the configured Ollama endpoint.

## 4. Source file reference

### `src/cli.ts`

This is the executable entry point. The shebang allows the compiled file to be
used as a command-line executable when installed through the `bin` field in
`package.json`.

#### `program`

`program` is the Commander.js application instance. It defines:

- The command name: `repopilot`
- The description shown by `--help`
- The CLI version

#### `suggest-commit`

The command defines four options:

| Option | Default | Purpose |
| --- | --- | --- |
| `--model <model>` | `qwen2.5-coder:7b` | Selects the local Ollama model |
| `--ollama-url <url>` | `http://127.0.0.1:11434` | Selects the local Ollama base URL |
| `--max-diff-chars <number>` | `12000` | Bounds the diff sent to the model |
| `--json` | disabled | Prints the validated object instead of a commit message |

The action converts `maxDiffChars` from Commander’s string option to a number,
rejects non-positive or non-integer values, reads the staged diff, creates an
Ollama client, and invokes the generator.

The final `try`/`catch` converts expected application errors into a readable
`Error: ...` message and sets a non-zero process exit code. This makes the CLI
usable in scripts without silently treating a failure as success.

### `src/git.ts`

This module is the Git boundary.

#### `getCachedDiff(): Promise<string>`

Runs:

```text
git diff --cached --no-ext-diff
```

`execFile` receives the executable and arguments separately. This avoids passing
a shell command string through a shell and prevents shell metacharacters from
being interpreted as commands.

The function configures a 20 MB output buffer. If Git fails, including when the
current directory is not a repository, it throws `RepoPilotError` with the
underlying failure detail.

The command intentionally uses `--cached`, so the function reads staged changes
only. It does not inspect the working tree or untracked files.

### `src/ollama.ts`

This module is the local model boundary.

#### `OllamaGenerateResponse`

Describes the part of Ollama's response used by the application:

```ts
interface OllamaGenerateResponse {
  response?: string;
}
```

The field is optional because external responses must be checked at runtime.

#### `OllamaClient`

This interface defines the dependency used by the commit generator:

```ts
interface OllamaClient {
  generate(prompt: string, model: string): Promise<string>;
}
```

The interface keeps the generator independent from HTTP details and allows tests
to provide a small fake client without starting Ollama.

#### `LocalOllamaClient`

`LocalOllamaClient` sends a non-streaming `POST` request to:

```text
<baseUrl>/api/generate
```

The request includes the selected model, prompt, and `stream: false`. The base URL
trailing slash is removed before `/api/generate` is appended.

The client reports three failure categories explicitly:

1. A non-success HTTP status, commonly caused by a missing model.
2. A successful response without a non-empty `response` string.
3. A network or connection failure, such as Ollama not running.

The default URL is loopback. A different URL is possible through the CLI option,
but callers should keep it pointed at a trusted local service to preserve the
offline-first privacy model.

### `src/commit-generator.ts`

This module contains the feature logic and model-output boundary.

#### `CommitSuggestion`

Represents the validated suggestion:

```ts
interface CommitSuggestion {
  type: string;
  scope?: string;
  subject: string;
  body?: string;
}
```

`type` and `subject` are required. `scope` and `body` are optional.

#### `buildCommitPrompt(diff: string): string`

Builds the model prompt. It:

- Requests one Conventional Commit suggestion.
- Lists the accepted Conventional Commit types.
- Requires JSON-only output.
- Specifies the expected fields.
- Tells the model not to invent claims.
- Wraps the diff in `<staged-diff>` markers.

The function does not call Ollama and does not change the diff.

#### `parseCommitSuggestion(raw: string): CommitSuggestion`

Converts untrusted model text into a typed suggestion:

1. Trims the response.
2. Removes an optional Markdown JSON fence.
3. Parses JSON.
4. Confirms the top-level value is an object.
5. Confirms `type` and `subject` are strings.
6. Confirms optional `scope` and `body` values are strings.
7. Trims fields and rejects empty required values.

It does not blindly trust the model. Invalid output becomes a `RepoPilotError`
instead of being printed as if it were valid.

#### `formatCommitSuggestion(suggestion: CommitSuggestion): string`

Formats a validated suggestion as a Conventional Commit:

```text
type(scope): subject

body
```

When no scope or body exists, those sections are omitted.

#### `generateCommitSuggestion(...)`

Coordinates the feature:

1. Rejects an empty or whitespace-only diff.
2. Truncates diffs longer than `maxDiffChars`.
3. Adds a local truncation marker.
4. Builds the prompt.
5. Calls the injected `OllamaClient`.
6. Validates the returned text with `parseCommitSuggestion`.

The default maximum is 12,000 characters. Truncation is done before the model
request so the size limit is predictable and local.

### `src/errors.ts`

#### `RepoPilotError`

A named application error used for expected operational failures. The CLI can
identify these failures through their normal `Error` behavior while preserving a
clear `RepoPilotError` name for debugging and future error handling.

### `src/tests/commit-generator.test.ts`

The tests use Node's built-in `node:test` runner and `node:assert/strict`.
They inject fake `OllamaClient` implementations, so unit tests do not require
network access or an installed model.

The test cases cover:

- Valid JSON parsing and formatting
- Markdown-fenced JSON
- Malformed JSON
- Missing required fields
- Empty diffs without an Ollama call
- Large-diff truncation
- Required prompt structure

## 5. Error handling

Expected failures are surfaced rather than hidden:

| Situation | Error source | Result |
| --- | --- | --- |
| No staged changes | `generateCommitSuggestion` | Suggestion is not requested |
| Not inside a Git repository | `getCachedDiff` | Git error is reported |
| Ollama is unavailable | `LocalOllamaClient` | Local connection guidance is reported |
| Model is missing | `LocalOllamaClient` | HTTP status and model guidance are reported |
| Empty Ollama response | `LocalOllamaClient` | Response is rejected |
| Malformed JSON | `parseCommitSuggestion` | Model output is rejected |
| Invalid CLI limit | `cli.ts` | Command exits with an error |

## 6. Development workflow

Install dependencies and build:

```powershell
npm install
npm run build
```

Run the tests:

```powershell
npm test
```

The test script builds first, then runs compiled tests from `dist/tests/`.
Generated output is ignored by Git.

Before opening a pull request:

```powershell
npm test
git diff --check
```

## 7. How to add a new command

When adding a future Git chore:

1. Add the feature logic in a focused module under `src/`.
2. Define an interface for external dependencies so the logic can be tested
   without Git, Ollama, or another service.
3. Add the Commander command and option validation in `src/cli.ts`.
4. Reuse `RepoPilotError` for expected failures.
5. Add unit tests for empty input, malformed external output, and the successful
   path.
6. Update this guide and the root `README.md`.
7. Keep modifications opt-in and confirmation-based. Never auto-commit, push, or
   overwrite a user file.

For changelog generation, the Git input should remain a read-only history command.
For README suggestions, produce a preview first and require explicit confirmation
before any future write operation.

## 8. Privacy and safety rules

The project follows these rules:

- Read staged changes only for commit suggestions.
- Do not read untracked files.
- Do not send data to a cloud service.
- Use the local Ollama endpoint by default.
- Never auto-commit or push.
- Never overwrite files without explicit confirmation.
- Bound large model inputs.
- Validate model output before displaying or using it.

Any new feature should preserve these rules or document an intentional, reviewed
change in behavior.
